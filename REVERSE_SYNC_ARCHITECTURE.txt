SSH Authentication Flow
=======================

Setup Phase (One-time):
  1. Generate key pair on DreamHost: ssh-keygen
  2. Copy public key to local: authorized_keys
  3. Create SSH config on DreamHost: ~/.ssh/config

Sync Phase (Daily):
  DreamHost Script
        ↓
  Reads: ~/.ssh/id_rsa_local (private key)
        ↓
  Connects to: ethel@192.168.2.10
        ↓
  Local server verifies: ~/.ssh/authorized_keys
        ↓
  Public key matches private key?
        ↓
  YES → SSH connection established ✓
        ↓
  SCP files
  SSH execute commands
        ↓
  NO → Connection denied, script fails ✗

Backup Strategy
===============

Before each sync, local server backs up:
  
  recipes.db                  ← recipes.db.backup_20241113_030015
  saved_recipes_json/         ← saved_recipes_json.backup_20241113_030015

After each sync, old files replaced:
  
  recipes.db (NEW)
  saved_recipes_json/ (NEW)

Full backup history preserved in sync_backups/
Easy recovery: cp sync_backups/recipes.db.backup_* recipes.db

Cron Schedule
=============

DreamHost Crontab Entry:
  0 3 * * * /home/f42widec/recipes_remote/sync_production_to_local.sh >> /home/f42widec/recipes_remote/cron.log 2>&1

Breakdown:
  0      = Minute (0)
  3      = Hour (3 AM UTC)
  *      = Day of month (any)
  *      = Month (any)
  *      = Day of week (any)

Frequency: Every single day at 3:00 AM UTC
  UTC 3:00 AM  = EST 10:00 PM (previous day)
  UTC 3:00 AM  = PST 7:00 PM (previous day)
  UTC 3:00 AM  = CET 4:00 AM
  UTC 3:00 AM  = IST 8:30 AM

Output: → /home/f42widec/recipes_remote/cron.log 2>&1 (capture all output)

Troubleshooting Quick Map
=========================

Sync not running at 3 AM?
  → Check crontab exists: crontab -l | grep sync_production
  → Check server time is correct: date (should be UTC)
  → Check cron log: tail -20 ~/recipes_remote/cron.log

Sync runs but fails?
  → Check sync log: tail -50 ~/recipes_remote/sync.log
  → Look for ERROR lines with specific failure
  → Run script manually: ~/recipes_remote/sync_production_to_local.sh

SSH connection fails?
  → Check private key exists: ls -la ~/.ssh/id_rsa_local
  → Check SSH config: cat ~/.ssh/config
  → Test SSH directly: ssh -i ~/.ssh/id_rsa_local ethel@192.168.2.10

Database not updating locally?
  → Check SCP succeeds: scp test.txt ethel@192.168.2.10:
  → Check disk space: ssh ethel@192.168.2.10 "df -h"
  → Check file permissions: ssh ethel@192.168.2.10 "ls -la ~/recipes_remote/recipes.db"

Flask not restarting?
  → Check start.sh exists: ssh ethel@192.168.2.10 "ls -la ~/recipes_remote/start.sh"
  → Test restart manually: ssh ethel@192.168.2.10 "~/recipes_remote/start.sh"
  → Check gunicorn status: ssh ethel@192.168.2.10 "ps aux | grep gunicorn"
